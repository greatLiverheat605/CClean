# CClean 首批页面规格：分类工作台

日期：2026-10-23（Asia/Shanghai）。用户已选择按首批计划收口并进入页面与任务细化；本文是待实现的页面规格，不是已完成能力或删除授权。
依据：[首批范围与 A-01～A-10](../../../../docs/08-first-release-plan.md)、[D-01～D-12 与产品边界](../../../../docs/07-product-replanning.md)、[真实盘点证据](../../../../docs/audit/2026-10-22-local-space-inventory.md)。
沿用已选分类工作台，不再比较布局或新建 HTML；首批新增规则仅验证本次 benchmark，补齐原 npm/旧转储闭环，其他对象只解释与保护。

## 1. 应用外壳与原入口映射

主导航固定为“空间与清理”“开发活动”“项目与版本”；范围管理、设置、清理历史为从属页面，不增加第四个工作区。
每次显式启动打开“空间与清理”；托盘恢复回到原页面、筛选、滚动与未批准选择。显式退出后再次启动不恢复任何旧删除批准。
窗口顶部显示页面名称与当前筛选范围；观察状态条显示正常/暂停/故障、已确认根数、最后有效更新时间及“管理范围”。
盘点范围与持续观察范围分开标注；不能用“全部磁盘”暗示所有目录已盘点，也不能用项目数充当全盘覆盖率。

| 原入口 / WPF 基础 | 新入口与保留行为 | 首批改变 |
| --- | --- | --- |
| `MainWindow` 的“空间与快清” / `OverviewView` | 空间与清理启动页 | 从固定 C 盘改为逐卷容量、用途分类与同屏说明 |
| `ProjectWorkbenchView` 的项目卡片 | 项目与版本 | 保留发现、搜索及路径去重；进入当前项目后显示关联范围 |
| 项目内 `FilesView` / `ProjectSpaceView` | 空间与清理中的项目筛选及“查看文件” | 统一当前范围与选择；不保留两套清理候选逻辑 |
| 项目内 `TimelineView` / `SessionsView` | 开发活动，保留当前项目上下文 | 时间线与会话详情可切换；自动发现不冒充运行状态或写入归因 |
| 项目内 `ProjectComparisonView` | 项目与版本 → 只读比较 | 保留已有能力、限制与取消；首批不增加归档或版本删除 |
| `CleanupPreviewView` / `CleanupHistoryView` | 空间与清理 → 预览 → 执行 → 结果；历史从属入口 | 所有清理入口使用同一已批准清单与结果语义 |
| `ProjectSetupView` | 管理范围；工具规则移入设置中的清理规则 | 补调整/移除监测，修正“左侧项目会话”等陈旧提示 |

## 2. 空间与清理：启动页 S-01

| 区域 | 关键内容 | 主操作 / 状态 | 验收 |
| --- | --- | --- | --- |
| 逐卷概览 | 卷标与盘符、总量/可用量、测量时间；不可访问或已离线单列 | 选择卷筛选、刷新容量；测量失败显示未知而非 0 | A-01/08 |
| 范围与盘点栏 | 磁盘/项目/工具筛选、当前根、已检查/待检查/跳过数量 | 选目录、盘点/继续、停止、管理范围；未盘点与空结果分开 | A-03/08/09 |
| 左侧用途列表 | 源码成果、配置凭据、Git/Agent 历史、依赖、构建产物、下载缓存、日志转储、未知 | 点行仅查看说明；每类显示已盘点大小、规则状态、覆盖提示 | A-01/09 |
| 右侧说明与明细 | 用途、关联依据、重要性、影响、重建条件；具体子范围与文件 | 展开依据、打开位置、复制路径、保留或加入本次选择 | A-01/02 |
| 本次选择栏 | 类别/根名称、对象数、各卷估算、保留数、当前筛选外已选数 | 查看全部选择、清空本次选择、预览本批；没有合格选择时禁用预览并说明原因 | A-02/03/06 |
| 次级入口 | 清理记录、Windows 存储设置、工具兼容与功能说明 | 系统工具明确标作外部窗口；其操作不计作 CClean 清理成功 | A-07/09 |

首次不勾选任何清理对象；无已确认范围时仍可读容量和做用户启动的只读盘点，不要求先开启监测才能理解占用。
分类按用途呈现；“用途已识别”“当前有规则”“当前合格”是独立信息。缓存名称、体积、旧日期均不能单独推出合格。
每类继续按工具/已确认根展开；Claude LocalCache 需拆出运行镜像与会话磁盘，不能将整个父目录显示为普通缓存。
列表默认按已盘点逻辑大小降序；切换到“已核验分配”时标明未知项与去重范围，不把缺项补为 0。
目录总量、逐文件分配、本批估算使用不同标签；只在实时资格复核后计算本批估算，父子行不能简单相加。
筛选仅改变视图；本次选择栏持续揭示筛选外选择，返回总览不清空保留项，也不扩大选择到新发现文件。
扫描显示当前阶段、已读数量、耗时和覆盖；无可靠总数时不伪造百分比。停止后保留部分结果，明确“未完成，可继续”。

## 3. 范围管理：从属页 S-02

入口为观察状态条“管理范围”及项目详情“关联位置”；与项目发现复用现有登记数据，不另建隐含观察清单。
关键列为项目/工具标签、完整路径、所在卷、来源依据、盘点状态、观察状态、最后有效时间、已知关联项目。
主流程为“选择项目 → 推荐关联目录 → 逐项查看来源 → 勾选确认 → 开始观察”；推荐列表默认不选，用户可手动补充未知工具目录。
推荐缓存不能仅凭项目路径标为独占；共享/未知关系始终可见。未知工具可纳入观察，但会话识别与清理能力分别显示未支持。
操作包括新增、改名、调整范围、暂停/恢复、移除监测；路径调整按旧范围停止与新范围重新核验处理，不把旧历史改写到新路径。
移除前说明“停止监测，不删除文件；已有历史保留并标为已移除范围”；相关预览失效，缺少当前观察的对象继续保护。
父子重叠显示已覆盖关系并复用已有观察，不能重复登记、计量或推导额外清理权限；盘符变化按卷身份重新确认。
卷离线、无权限、重解析点、不支持的环境分别显示原因；不能因推荐失败而宣称不存在该工具。WSL/Docker 内部不提供新增入口。
状态为未确认/建立基线/观察正常/暂停/观察不完整/不可访问/已移除；页面错误定位到具体范围，不盖掉其他正常行。验收：A-05/06/08/09。

## 4. 说明卡契约与三个具体实例

每张说明卡固定回答“是什么”“与谁有关及依据”“为什么保留或处理”“处理影响”“重建/恢复条件”“占用与覆盖”“当前操作”。
重要性用具体价值表达，例如“可能是唯一对话历史”“保留验收证据”；不展示没有证据的安全评分或一概“放心删除”。
完整路径、生成记录、规则版本、对象身份放在可展开详情；关键影响不能只藏在 tooltip。下列数字仅为 2026-10-22 盘点证据。

### 实例 C-01：CClean benchmark

- 标题“CClean 合成压测数据”；位置 `D:\CCleanLab\CCLEAN-20260917-DEV\benchmark`；用途为性能/可靠性测试样本。
- 历史盘点“整个范围已观察分配约 20.340 GiB，100,002 文件”；其中 100,000 个 fixture 逻辑 20 GiB、分配约 20.218 GiB，另含 `index.db` 约 124.719 MiB 与 19 B 的 `.cclean-sandbox` 根标记。
- 用途卡明确父范围包含样本和索引/标记，不得把 100,002 文件统称为可再生成样本；首条规则仅验证本次 run 对应的 `file-*.bin`，命名匹配本身不足以证明来源。
- 价值“测试报告与复现方法必须保留；样本能否再生成仍需证明，重新生成不等于恢复原测试现场”。
- 依据显示对应生成代码、参数、工具版本、范围及混入检查结果；证据缺失显示“待验证”，不出现可执行勾选。
- 影响“处理后该批样本不再存在，复测须按记录重新生成”；重建时间/下载代价未测则写未知，不承诺固定耗时。
- 操作“查看复现依据”“打开位置”“保留样本”；只有已验证且不活跃的具体 fixture 可加入预览，本批预计释放保持待核验；`index.db`、`.cclean-sandbox`、artifact 报告、复现方法及未知项锁定保留。验收：A-01～05。

### 实例 C-02：Codex 会话与历史

- 标题“Codex 会话与任务历史”；将 `.codex/sessions`、`archived_sessions` 与历史数据库分项呈现，不混入插件、运行时或工作副本。
- 历史盘点的 sessions 约 1,396.99 MiB、archived_sessions 约 318.58 MiB 标注为按路径逻辑大小及观测时间。
- 价值“用于保留对话和开发上下文，可能没有其他副本”；影响“删除可能永久丢失历史，重新安装不能保证恢复”。
- 依据“已知持久数据路径与文件元数据”；不读取正文来评分，也不声称 JSONL 与数据库是可删除的重复内容。
- 状态“受保护，首批不提供清理”；主操作“打开位置”“查看占用明细”。未知关联不阻止解释，但不能变成删除资格。验收：A-01/02/09。

### 实例 C-03：当前没有可清理候选

| 具体原因 | 页面说明 | 可行下一步 |
| --- | --- | --- |
| 未盘点或部分盘点 | “尚未取得此范围完整结果”，不显示为“占用 0” | 开始/继续盘点，查看未检查范围 |
| 无已验证规则 | 如 G 盘 target：用途可能为构建输出，首批只读解释 | 查看构建关联依据、打开位置；不提供绕过规则按钮 |
| 活动或消费者未知 | “正在使用或无法确认当前活动”，指出受影响范围 | 查看观察/消费者状态，条件变化后重新检查；不要求用户强退进程 |
| 规则未启用或版本不支持 | 展示当前版本与规则要求；不假装工具受支持 | 查看清理规则与验证条件，完成条件后重新预览 |
| 全部已保留或确实无合格项 | 区分用户保留、规则排除、实际空目录 | 查看保留项/排除原因，调整筛选；不得解除系统保护 |

无候选场景仍保留用途卡、覆盖信息和可操作下一步；不只弹一句“没有垃圾”。验收：A-01/03/06/09。

## 5. 本次选择、保留与偏好

行高亮用于查看详情，独立复选框表示“加入本次处理”；Space 仅切换当前合格对象，双击或 Enter 查看详情不授权处理。
显式批量操作标明范围，例如“加入当前页合格项（N）”；跨页操作须显示完整作用范围与已核验数量，未扫描部分不随之选中。
本次保留优先于类别偏好，跨筛选、翻页、重扫和后续批次生效；新发现或身份变化的文件不能继承旧执行批准。
保护项复选框不可用但原因可聚焦查看；“全选”只作用于合格项，清单必须列出排除数量和原因。
首批偏好按“用途类别 + 工具标识 + 已确认根”限定；保存时直接写明作用范围，可在设置删除，不能默认为本机同类对象全局授权。
偏好仅形成可见建议，本次选择操作才采用建议；规则、工具版本、重建影响变化后先重新说明。显式退出清空旧批准，保留已保存偏好。
npm 等关联对象按验证过的完整组合展示：保留某成员可能导致整组保留，必须解释并重新展示；不能偷偷加选搭配对象，也不能虚构任意拆组能力。
本次选择变更立即更新数量与逐卷估算；已生成预览随变更失效。若对象不可访问，只能显示未知与排除，不能当作用户取消。验收：A-02/05/06/10。

## 6. 独立预览、执行与结果

### S-03：预览确认

关键内容：本批类别/规则/根与卷、精确对象数、估算及未知项、排除/保留数、有效期、处理影响；明细支持路径搜索及分页，不改变批准范围。
主操作“返回调整”“确认永久删除本批 N 项”；确认前显著写明“不进入回收站”，初始焦点不得落在破坏性确认上。
多规则按独立范围分组，一条未启用/失败/活动未知不伪装成全批失败；共用消费者或保护根等真实依赖仍须一致判断。
100,002 文件规模由系统形成有界有限批次；展示本批、已知剩余、用户保留与未扫描量，不能要求用户手工切目录绕过 1,000 项限制。
保留现有 5 分钟清单有效期；过期或资格变化禁用确认并给“重新预览”。新文件不自动加入，下一批也需独立预览确认。
状态：正在复核/预览就绪/无合格项/部分检查/已取消/已失效；取消不产生删除，返回调整保留本次意向。验收：A-02～06/09。

### S-04：执行进度

关键内容：本批已处理/总数、成功/跳过/失败/未执行计数、当前阶段与对象、已耗时；结束前不以估算大小宣称释放完成。
主操作“停止后续清理”“查看本批清单”；执行中禁止第二次提交，改筛选或切页不能改变已批准范围，全局状态提供“返回执行任务”。
停止后显示“停止请求已收到，当前项收尾中”，完成收尾后再显示已停止；停止不能恢复已删除内容，程序不得静默继续下一批。
自身已批准删除与真实外部活动分别处理，界面要说明后续停止/跳过原因，不要求用户关闭观察以跑通清理。
关闭主窗口进入托盘并继续本批；明确“退出”先停止后续项、安全结束当前项，再停止观察。异常退出按中断记录处理。验收：A-03～08。

### S-05：结果与清理历史

关键内容：任务时间/版本/本批范围、成功/跳过/失败/未执行及未知结果；每项可查原因，历史与当时清单绑定。
逐卷并列“已处理对象分配”“系统可用量前后变化”，后者允许负值或测量失败，并说明其他进程影响；不能只显示一个“已释放”大数字。
主操作“查看未处理原因”“重新预览剩余项”“返回空间与清理”“清理历史”；重新预览需重新读取当前对象，原任务不自动续删。
历史显示人可读的状态与本地时间，技术事件代码放详情；“中断后检查”不命名为“恢复文件”。无记录与读取失败分别反馈。
结果页给出对应重建方法及条件；本次未测消费者重建时不得宣称“完全不影响开发”。历史读取失败不抹掉已知本次结果。验收：A-04/07/09/10。

## 7. 保留工作区与设置

| 页面 | 关键内容 | 主操作 / 状态 | 验收 |
| --- | --- | --- | --- |
| S-06 开发活动 | 当前项目/时间/工具、变化聚合、会话上下文、覆盖缺口；区分初始存量与观察后变化 | 筛选、刷新、图/键盘列表、查看当前目录文件；无历史、暂停、离线与失败分别说明 | A-01/05/08/09 |
| S-07 项目与版本 | 项目名称与完整路径、关联工具/跨盘位置、登记状态、当前索引、现有版本比较 | 发现/继续、选择项目、管理范围、选择另一版本并只读比较、取消 | A-01/08/09 |
| S-08 设置与规则 | 主题、确认范围、按工具的能力表、已保存偏好、已验证规则的启用/条件、版本与功能说明 | 调整设置、撤销偏好；规则未验证不出现可启用状态，新规则升级后默认关闭 | A-02/06/09/10 |

开发活动首批保留已有轻量观察与入口联动；自动发现会话继续标运行未知，不把同时活动写成创建者证据，不展示未实现的增强追踪按钮。
项目内“文件与空间/清理位置”跳转 S-01 并带项目根；时间线查文件保留当前目录边界。切回原工作区恢复原筛选，不跨项目串数据。
版本比较保留当前读取预算和未比较提示；“相同”仅对已比较文件成立。首批不扩成多版本自动整理，独有/敏感/未比较内容继续保留。
设置从窗口和托盘进入，清理规则只允许已验证实现；Windows 侧 WSL 转储不描述成 WSL 内部支持，未知工具允许登记不等于清理适配。
托盘提供“打开 CClean”“观察状态/暂停或恢复”“设置”“退出”；重复启动只恢复同一实例，恢复过程中不再创建监视器或执行器。

## 8. 状态、键盘、DPI 与主题约束

| 状态 / 边界 | 必须看见的反馈 | 保留与恢复规则 | 验收 |
| --- | --- | --- | --- |
| 快速切页、筛选、重新扫描 | 标明新范围与加载状态，旧请求结果不得覆盖新范围 | 保留当前保留意向；不沿用旧可执行预览 | A-02/03/09 |
| 取消发现/盘点/比较/预览 | 停止中的反馈，随后已停止或已取消；保留的部分结果注明覆盖 | 返回入口、重试/继续各自正确；取消不发布未完成的清理资格 | A-03/09 |
| 无权限、卷离线、预算不足、审计不可写 | 具体范围/阶段和原因，不能用空表代替错误 | 不扩大执行；可查已有结果、容量及系统工具入口 | A-06～08 |
| 观察故障、退出重启 | 旧快照时间、观察空窗、清理保护及重新建立基线状态 | 不补造离线历史，不自动续删；按协议重新核验 | A-05/07/08/10 |

Tab 顺序按导航 → 范围/筛选 → 分类 → 明细/说明 → 本次选择 → 主操作；Tab/Shift+Tab 可达所有核心动作，表格提供方向键与明确复选行为。
预览/对话框支持返回与 Escape 取消；执行页 Escape 不冒充撤销删除。关闭弹层回到原触发控件，验证失败聚焦错误说明或首个错误字段。
所有操作和禁用原因具备 UI Automation 名称/关联说明；状态以完整语句适度播报，不抢焦点、不逐文件高频朗读。
长路径可换行、复制和键盘展开；关键风险、保留原因与主操作不只在 hover 出现。不可用控件的原因须有独立可聚焦说明。
继续使用现有系统中文字体与语义资源，浅深主题保持文字对比度至少 4.5:1；状态同时用文字，不依赖红绿区分，不另引入主题框架。
验证常用窗口与 125%/150%/200% DPI、跨屏缩放；收窄时分类与说明可上下排列，保持同一工作台和选择栏，不能裁掉确认/停止按钮。
大列表分页/虚拟化，进度更新合并且不重建整表；繁忙时阻止重复动作而非冻结整窗，滚动或后台刷新不能挪走焦点。对应 A-03/09/10。

## 9. 用户验收与完成出口

场景一：用户在正式安装版独立查看 benchmark、Codex 历史、Claude LocalCache 与 G 盘 target，说明用途、保留价值及当前为何可/不可处理；对应 A-01/09。
场景二：用户保留一批合成样本，翻页、筛选、返回和进入后续批次，核对报告/复现方法未选、具体保留生效；对应 A-02/03/09。
场景三：实施阶段用隔离样本完成多批真实 UI 执行、停止、查看逐项/逐卷结果并重建；记录每批耗时、目标规模确认次数与困惑，不能只测 3 项通过；对应 A-03～07。
用户需靠开发者口头解释才能继续的场景仍未通过；记录入口、范围、操作、预期/实际、修复版本与复验，不用页面数或自动化通过数替代使用结果。
同一交付版本验收安装升级、偏好/历史迁移、新规则默认关闭、资源预算及预先固定时长的多日观察；沿用原指标与失败记录，对应 A-08～10。
本文不执行上述验收或删除；待开发完成后，证据需关联源码提交与安装包版本，未实现/未测场景保持未完成，功能摘要与真实能力同步。
