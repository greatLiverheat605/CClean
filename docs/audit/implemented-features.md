# CClean 已实现功能审计 — 0.1.5

审计日期：2026-09-19。用途：Windows 本机个人开发空间观察与受控清理。此文档按源码、自动化测试和本机观察区分功能完成度，不是全部发行门槛通过证明。

## 结论

- 已有可用的空间盘点、项目监测、变化时间线、文件索引、手动会话、受控清理及本地审计。
- 0.1.5 将项目卡片设为首页，项目内统一承载开发时间线、文件与空间、清理位置和会话。
- 0.1.4 新增 Codex / Claude Code 会话元数据自动发现、独立会话页，并修补所有现有主页面的导航/空状态/保护入口。
- 自动发现不证明工具正在运行，也不证明某条文件变化来自某个会话；未知状态继续保护。没有实现全盘一键安全清空、版本源码自动去重删除或任意开发缓存清理。
- 原 10 万文件内存指标失败、多日稳定性和跨机器发行验证仍保留，不能用本次小规模发现结果替代。

## 项目详情边界

文件和时间线在数据库 LIMIT / OFFSET 前按登记 ID 与目录边界过滤，不会把 app-backup 混入 app。发现的登记根子目录复用所属根的监测记录，并继续按子目录过滤；覆盖缺口以登记根为单位保守展示。未登记项目只有会话与只读空间盘点，不补造文件历史，需用户显式加入持续监测。

构建目录名、版本文件夹名和规则覆盖仅为线索。只有选中具体位置并通过当前保护规则复核后，才显示候选数量；进入清理中心仍重新预览和单独确认。所有真实用户数据在验收中保持原样。

## 会话发现的数据范围

默认来源：`%CODEX_HOME%/sessions`（未配置时为用户目录 `.codex/sessions`）及用户目录 `.claude/projects`。不会访问凭据文件或工具私有 SQLite 数据库；不扫描 ZCode 模型输入输出日志。

读取 JSONL 有界前缀：Codex 第一行，Claude Code 最多前 16 行，总上限 262,144 个字符。前缀可能含工具指令或消息字段，但只提取会话 ID、cwd、时间，正文不展示、不保存、不上传。文件末次写入时间作为最近更新提示，不代表最后一次人工操作。没有时间字段时使用文件创建时间，不声称它是精确会话开始时间。

发现结果仅存在应用内存，按文件长度与修改时间跳过未变化文件，按工具与会话 ID 去重。最多缓存 2,000 个文件，待处理目录队列最多 2,000；单批最多 200 个对象/约 2 秒。异常、重解析点、云占位、未知格式和上限会计入跳过项。异常轮次保留旧记录保护范围，不把读取失败当会话结束。

不支持：归档会话目录、自定义 Claude 数据根、WSL 内部 Linux 路径、网络路径、ZCode 自动发现、工具实际活跃/结束状态检测。无受支持记录时展示手动入口，不伪造会话。

自动发现项目路径会进入未知活动保护；只有用户点击登记才启动文件监测。某会话 cwd 是用户主目录等宽范围时，可能保守保护其整个子树，导致部分清理被拒绝。发现记录不会写入开发时间线的“已确认会话归因”。

## 清理保护审计

- 删除资格来自唯一已验证规则及当前对象复核，不来自占用大小、目录名称或会话结束。
- 保护源码、配置、文档、凭据、Agent 会话数据、发现的会话项目及应用自身数据；转储规则另保护全部登记项目。登记缓存根仍须按独占规则和活动状态判断；特殊属性、未知身份、命名流、多硬链接、重解析点、占用/活动未知均拒绝。
- 清单有效期 5 分钟，绑定规则、活动范围、保护范围与文件身份；改变上下文会使清单失效。
- 永久删除前显式确认，执行时重新核对身份并写审计；审计不可写、低空间/预算不足时保守停止。停止只能阻止后续项，不能恢复已经删除的文件。
- 旧 WSL 转储规则仅处理当前用户 Temp/wsl-crashes 的直接 `wsl-crash-*.dmp`；保留最新及 48 小时内文件。删除会失去对应故障诊断，不删除 WSL 发行版、项目或开发依赖。
- npm 仅支持已配置的 npm 11.19.0 独占缓存规则，清理后可能需要联网重建；不承诺不影响离线开发。默认/共享缓存不会自动获得授权。
- Windows 清理器由系统展示清单并确认；CClean 不控制系统工具的选项。用户仍应保留需要的下载文件和回收站内容。
- 项目多个版本文件夹只按同父目录名称提示，未作内容等价验证，绝不据此自动删除源码。

## 验证记录

- 0.1.5 隔离运行目录的真实 WPF 验证：项目卡片、Alpha 2 文件 / Backup 1 文件切换、时间线节点、项目内会话空状态及深色主题已核对；构建目录复核为未知来源保护，候选入口禁用，没有执行真实删除。

- 0.1.5 本轮 55 项 MvpP0 通过；新增项目目录去重/子目录映射/系统及无效路径排除、分页前目录隔离/历史与缺口隔离测试。
- 0.1.4 的 53 项 MvpP0 回归通过；新增三组会话发现测试覆盖分批续扫、去重/增量、取消、破损写入保留保护且不阻断同目录新文件、Claude 前缀、相对路径/超大头部拒绝、链接来源拒绝。Release 构建零警告、零错误。
- 本机只读发现探针：47 个会话，Codex 37、Claude Code 10；首轮 14 项跳过/不支持、一轮约 0.42 秒；最终修正后的复测为同样 47 个会话、6 项跳过、约 0.69 秒。数量随用户工具活动变化，非性能门槛承诺；没有将真实项目路径写入本报告。
- 本机会话页：47 条展示、Claude 搜索筛到 10 条已观察。七页导航、首页系统排除提示、时间线/文件/记录空状态、文件按钮禁用、项目目录选择入口、会话手动页及深色主题均已实际打开核对。清理预览不执行真实删除；安装结果由本机交付回执记录。
- 本轮未删除用户真实项目、缓存或转储。清理删除测试使用合成沙箱；历史真实转储候选大小不是当前可释放容量保证。

## 未完成与后续优先级

1. ZCode 的安全元数据适配、可证明的真实会话状态与精确工具归因尚未实现；需要独立验证，不能只靠进程名称推断。
2. 旧版本目录内容比较、迁移/归档建议和可靠回滚尚未实现，因此没有自动删除旧项目目录按钮。
3. 10 万文件样本工作集约 267.19 MiB 超过原 200 MiB 门槛的失败记录保留；旧版小样本 15 分钟稳定运行证据不能代替新版大规模/多日验证。
4. 新版多日稳定性、完整 DPI/无障碍组合、干净 VM 跨机器安装、签名和发行门槛仍待完成；ETW/USN 可选增强不在本版产品能力中。
