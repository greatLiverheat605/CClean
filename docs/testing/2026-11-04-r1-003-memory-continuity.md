## 已实现

1. `DirectoryMonitor.Observe()` 不再反复复制完整通知历史，改为共享标准库不可变集合。通知仍即时进入有界历史，条数 2,048、路径字符总量 262,144 和 `DroppedThrough` 缺口语义不变。旧观察不受后续通知修改。
2. `ObjectCleanupReview` 依据有序序号定位新通知后缀，避免每次从头遍历旧通知。原始新通知仍持久化，序列丢失/不完整、未知事件和故障仍拒绝继续。
3. 元数据读取在完成新句柄的最终路径、身份、全部元数据和流枚举后，才复用相同的身份字符串和快照值；不缓存删除资格、不略过读取。校准扫描沿用这一路径，避免先分配临时身份/快照再丢弃。
4. 增加仅内部可用的 `PreviewNextSegmentResearch`，沿用单份继续证据，严格绑定契约。研究成功不会给普通 `PreviewNext` 提供证据；尝试切换契约、重放或失败会失去继续资格。每批仍生成新 ID、新的未批准有限清单，并须独立明确确认；不能刷新前批证据期限。
5. 仅继承前批最后 1,000 条回执；研究最多再保留当前 10,000 项，共最多 11,000 条。丢失更早回执的迟到通知仍安全停止。普通对象契约维持最多 2,000 条，普通产品入口保持严格和 1,000 项。
