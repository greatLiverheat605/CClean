## 2. 每个 profile 的七组有限场景

下表中的 profile access 分别为 `0x80` 与 `0x81`。`0x81` 对照用于观察包含数据读取/目录列举访问位后的共享兼容检查；不能从访问位名称预判消费者是否实际受阻，也不能将 `0x80` 的反例推广为所有写入约束均无效。

| 组 | 严格对象与共享方式 | 需要记录的事实 |
| --- | --- | --- |
| 父目录元数据，共享读 | 候选父目录；profile access，share `0x1` | 已打开的 `FILE_WRITE_ATTRIBUTES | FILE_READ_ATTRIBUTES` 句柄在租约前后修改时间；新属性句柄修改时间；Hidden 属性开关；普通目录读取能否打开。 |
| 父目录元数据，不共享 | 同样的独立父目录；profile access，share `0x0` | 检查无共享是否真能阻止属性时间写入，同时记录普通读取受到的影响；不能把“更严格”当成“覆盖全部操作”。 |
| 父目录与子树 | 只约束候选根目录，share `0x1` | 子树中预先持有的数据写和 DELETE 句柄；同长度写入、新写入句柄、0 B 新建、两种删除；两棵独立三层嵌套目录分别移入及移出，避免前者被拒绝就丢失后者验证。目录句柄并不预先声明递归覆盖。 |
| 叶子已有属性句柄 | 叶子 profile access，share `0x1` | 与既有 `0x180` 属性消费者是否兼容；若取得，原句柄是否仍能修改时间；关闭原消费者后能否再取得租约。 |
| 叶子已有数据写句柄 | 同上 | 既有 `0x82` 数据消费者是否使租约取得失败；若取得，原句柄是否仍能同长度写入；关闭后重试取得。 |
| 叶子已有 DELETE 句柄 | 同上 | 既有 `0x10080` DELETE 消费者是否使租约取得失败；该组只保持访问权，不实际标记删除；关闭后重试取得。实际已有 DELETE 句柄删除由子树组覆盖。 |
| 叶子消费者与取消释放 | 同上；无预先消费者 | 新数据写/DELETE 访问在租约前、持有中及释放后的对照；新属性时间写入；受控取消经 finally 释放后同路径操作恢复，最后只删除本组样本。 |

每次操作分别记录 `succeeded`、错误码 32 的 `sharing-violation` 或其他失败。无法取得严格句柄时不伪造持有中动作；拒绝访问、权限或前提失败不冒称共享锁已阻断。写入验证读取本次 16 B 样本，保持原长度；未声称 flush 到介质。

叶子取消释放组额外输出 `dataConsumerRejectedDuringLease`、`deleteConsumerRejectedDuringLease` 与 `consumersRecoveredAfterRelease`；这些字段来自各阶段实际操作，不预设 `0x81` 必须产生何种结果。每组及每个 profile 分别给出覆盖结论，总汇总只标记 `profile-specific-results-only`，不将一个 profile 的反例当成另一个 profile 的结果。

## 3. 判定规则

- 脚本的 `passed` 仅表示该组所列操作、观察与释放检查完成。`protocolQualified=false`、`productionExemptionEnabled=false` 固定保留；操作在租约内成功，是该 access/share、对象与动作覆盖不足的证据，明确标记 `coverageConclusion=insufficient`。没有复现反例时仍为 `not-established`，不反向证明充分，也不作跨 profile 推断。
- 父属性/子树修改成功，可否定相应共享句柄能够排除该类活动。既有写/DELETE 句柄使叶子租约失败，只证明该对象上的兼容检查，不证明父目录或其他子项无活动。
- 取消测试是同步操作后的受控异常和 finally 释放；记录耗时但不作为慢盘、内核阻塞、UI、2 秒取消或退出验收。
- 操作均由本进程控制，不等同真实工具兼容性、进程归因或系统全局业务锁；没有开展新的 USN 读取，不以空窗口、路径、时间或末态进行生产豁免。

既有 [USN 反例](2026-10-23-r1-003-observation-diagnostic.md) 保持有效：重复外部修改仍可能没有新原因记录。即使本轮部分共享限制有效，也不能自动补成生产来源证明。
