# R1-003：WPF 空闲复验与研究跨批内存

状态：`in_progress`。本轮原始证据在 `artifacts/r1-20261104-memory-followup/`，保留其中全部失败 TRX 和此前 `artifacts/r1-20261104-next/` 的证据。样本为新建隔离根的 100,000 个三字节文件；不是约 20 GiB 实际规则样本。研究扫描租约仍只供内部隔离入口，普通产品入口严格且最多 1,000 项。

## 归因与修改

- `WorkspaceViewModel` 的 previous 与监测器当前快照共享同一字典；当前 WPF 探针等待自动校准，空闲期 revision 保持 2，没有再排队第三次完整扫描。监测字典仍持有 100,000 个 `FileSnapshot`；校准中短暂并存新旧扫描字典。无堆转储工具，不能把 WPF/CLR/SQLite 原生页与托管活对象精确拆分。
- 研究宿主在首扫后约 150 MB、首批审计恢复后约 195 MB；第二批执行中出现生命周期峰值。此前 `ObjectCleanupReview` 的 async 调用者仍引用前批 review，新 review 只需其已核查证据；现构造后释放旧引用。review 原先还长期持有完整 `CleanupPlan`，运行期实际只需 ID、契约、创建与到期时间，现只保留这些值。单对象研究复核保留全部根、父目录、同句柄元数据及保护检查，省去两次 `GroupBy`。
- 研究租约释放后，扫描完成信号原先在第一扫结束即发出，即使扫描期间又收到 watcher 通知。现在等这些通知对应的后续扫描完成；扫描开始前到达的合并提示纳入当前扫描。原始通知、队列/原生缺口仍即时记录。连续通知或前批 5 分钟期限到期仍停止，不续期、不继承批准。新增受控“第一扫中通知”回归。
- 仅 WPF 探针增加最终退出码保留；`Measure-AppIdle.ps1` 的测试环境变量可在完整采样及报告写入后受控返回 1，用来检查子进程失败向外层传播。正常采样规则、200 MiB 门槛与 600 秒窗口未变。

- 最终 Release 构建：0 警告、0 错误。监测定向 11/11，跨批定向 47/47，单项保护对抗 35/35；这些测试彼此及全套有重合，不相加。
- 最终非显式容量过滤组 `final-noncapacity-20261105.trx`：272/273。唯一失败是普通对象契约 1,000 项在 5 分钟到期，完成 715 项；此前同用例 `review-lifetime-focused.trx` 为 37/38、只完成 669 项。两次零应用/原生缺口；不能把旧版 270/270 写成本轮最终通过。
- 两批 `research-two-batches-review-scalars.trx` 为 0/1：两批均完成，资源门槛失败。后续两次为第二批预览拒绝或前批证据到期，均保留首批结果及未批准对象。十批测试未运行；本轮未重跑子进程崩溃恢复 3/3，旧证据仍保留。
- 完整 WPF 同版两次空闲资源通过，但研究宿主超过 200 MiB、`ObjectReviewV1` 组件 1,000 项当前时限失败、连续十批及实际规则样本未通过。R1-003 仍为 `in_progress`，R1-004/005/006/008 不放行，研究租约不接入产品。
