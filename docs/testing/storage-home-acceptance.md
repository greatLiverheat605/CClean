# 0.1.2 空间首页与快速清理验收

目标：本机个人使用，改善空间入口；发现项目与版本副本线索，优先处理项目无关占用。用户明确版本指多个项目文件夹。

| 检查 | 结果 |
| --- | --- |
| 回归 | 49 项 MvpP0 通过，构建零警告/零错误 |
| 扫描边界 | 分批 / 取消 / 继续计量正确；不遍历符号链接，不读取内容；依赖清单不当作项目 |
| C 盘 UI | 第一批 105201 文件、42.57 GiB 部分逻辑量；继续后停止于 156781 文件、104.12 GiB，明确部分结果；不是全盘已完成，也不是可释放量 |
| 发现精度 | 首轮包含已安装应用清单，随后已排除系统、已安装程序和常见工具缓存中的项目识别；标记发现仍为线索，不是完整项目清单 |
| 副本 UI | 两个合成项目 sample-v1 / sample-v2 正确显示疑似版本副本、占用条、完整路径与保留源码说明 |
| 视觉 | 浅深主题实测；修正主按钮文字对比度，详情可滚动访问；未替代原 200% DPI 验收 |
| 系统清理 | 按钮打开 Windows 磁盘清理分类清单，随后取消；未执行真实清理 |
| 旧转储核心 | 合成真实删除仅处理旧文件；保留最新、近期、源码、子目录与被写入占用文件；新增转储使旧清单失效 |
| 旧转储 UI | 本机 10 项中 9 候选，分配估算 45.02 GiB、排除最新 1 项；二次确认默认“否”，验收选择“否”取消；真实文件全部保留 |

规则范围：当前用户临时目录下 wsl-crashes，直接子文件 wsl-crash-*.dmp；至少 48 小时，保留最新时间并列的所有文件。未知元数据停止；身份、流、硬链接、写入占用、清单时效、上下文变化和审计保护沿用现有执行器。该规则不写入默认启用的 npm 配置，不依赖关闭用户 Node/WSL 进程。

盘点最多 5 万目录，仅保留聚合元数据；不自动监测整盘，不自动删除项目副本。常见缓存大小不意味着全部可删，自定义缓存位置未自动推断。正式 npm 清理 UI 执行、跨环境安装、200% DPI 与原大样本 200 MiB 指标仍待验 / 失败。本版本没有重跑多日稳定性，不继承 0.1.1 的短时数据为新版本通过。

实际路径、数据库、测试 fixture 和安装回执只保存在本机 artifacts，不提交仓库。
