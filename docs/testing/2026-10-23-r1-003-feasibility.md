## 3. 协议结论与下一步边界

- 原 API 只形成最多 1,000 项清单，1,001 项起标为截断并拒绝执行；10 万项即使机械分批也需要 100 次确认，不能据此宣布体验可用。
- 保留 5 分钟有效期、8 MiB 审计清单和既有预算。历史 `Events()` 的 3,000 条上限与恢复 `Take(1000)` 仍在；恢复还逐项 `LastOrDefault()` 扫描事件，成本为对象数乘事件数，不能只提高预览常量。完整全集研究清单仅作序列化/拒绝验证，不传入 `ExecuteApproved`。
- 安全归属需要另列技术方案：核验带身份、原因和连续性的数据源能否覆盖具体删除及父目录变化，并将逐项执行审计回执与原始观察证据关联。USN/扩展通知本身不提供进程归因，尚未证明它们足够；不能先承诺一定能安全豁免。
- 若考虑预先固定全集、内部分页，必须先证明完整集合预持久化、禁止追加、分页审计/恢复、取消及过期行为；内部翻页不续期。改变清单存储上限或有效期属于重大协议取舍，本次没有实现或默认批准。

当前任务应保持 `in_progress`。R1-004/005/006 的依赖出口尚未满足；可继续不依赖本任务的用途、范围与页面工作。旧计划状态不随本证据改写。
