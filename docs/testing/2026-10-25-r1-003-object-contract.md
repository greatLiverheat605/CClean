# R1-003：D-13 对象级契约实施与隔离验证

日期：2026-10-25（Asia/Shanghai）。本轮契约实现与隔离组件验证完成；**R1-003 整体仍未通过，正式规则及普通 UI 未启用新契约**。

## 1. 本轮实现

- `CleanupPlan` 显式绑定 `StrictActivity` 或 `ObjectReviewV1`；上下文指纹同时绑定规则、保护范围、会话、观察器身份及通知位置。严格入口保留，新路径由隔离验证显式使用。新契约的审计清单采用 v2，旧 v1/完整旧格式仍可读取，初版隔离 v1+Contract 记录也可核查；读取不恢复执行授权。
- DirectoryMonitor 保留真实 LastActivity，并另存有界原始通知（最多 2,048 条、262,144 个路径字符）。每个观察器有独立身份、序列与丢弃位置；执行游标落后于保留窗口便停止。原生/应用通知缺口、故障、观察代次及本批新增扫描缺口仍使执行失效，不用后续成功扫描抹掉本批缺口。
- 同句柄删除成功且逐项审计落盘之后，才登记该对象回执。对应 Deleted 通知，以及已绑定身份且无命名数据流的父目录 Changed 通知，可以在复核剩余批准对象、规则和消费者后继续。日志明确记作 `Source=undetermined`，不声称唯一归因。
- 剩余对象仍逐一核对元数据、根身份和保护条件；复用已有父目录稳定句柄读取，避免重复打开同一祖先链。复核之后重新取得消费者/会话上下文，删除标记前再次检查通知水位、取消和到期。
- 应用内互斥协调扫描与自身删除，避免自身删除与扫描枚举竞争。watcher 始终开启，外部写入不受该互斥限制。等待扫描时支持取消，资源/到期条件不放宽。
- 原始通知和继续决定分别持久化；审计预算纳入通知负载。5 分钟、8 MiB、1,000 项上限、每项结果落盘、取消和重启不续删均保留。

## 5. 未完成出口与后续顺序

1. **跨批与规模仍未通过。** 当前每次容许通知都复核全部剩余对象，总体最坏仍为 O(n²)；1,000 项实测不能推算 10,000/100,000 项能在 5 分钟内完成。生产上限没有提高。10 万项至少 100 份批准只是算术下界，下一批还有近期活动阻拦；本轮实际 UI 确认次数为 0。下一步应先设计和验证跨批预览/批准边界及成本，不能直接复用上一批授权或静默续期。
2. **真实规则分别验证。** 原 benchmark 历史生成凭证缺口、保留资料与可再生成资格仍未解决；npm 组合一致性/真实消费者重建、转储保留规则均待独立闭环。宿主上 Node 活跃导致当前 npm 入口无法正向验证，本轮没有缩小消费者识别范围。
3. **保持风险边界。** 外部元数据活动可以混入已容许通知，未知消费者可能受到缓存缺失/重建/失败影响。通知交付与消费者枚举均非全系统业务锁；审计记录截至实际采集水位，不声称排空未来异步通知。复核失败仍停止。
4. 安装版、完整键盘/多 DPI、真实用户理解与操作、资源预算和 72 小时稳定性继续待验；旧 200.73 MiB 门槛失败及旧 28 项任务未改写。

R1-003 保持 in_progress；R1-004/005/006 依赖未放行，R1-007/009 保持 pending_validation。没有安装、提交、推送或清理既有用户文件。仅本地任务表同步，MCP 仍不可用。本轮不再追加同类 USN/写入租约归因研究。
