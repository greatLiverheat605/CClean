## 实现

- `ProjectRegistry` 在原 `projects.json` 上支持改名、换根、暂停、移除及显式共享关联。配置修订与物理根版本分开；旧配置保持原历史键，只有换根生成新观察键。共享关系不新增 watcher，换根不会追认旧关联；保留根的重叠、系统路径、64 根预算。落盘成功后才发布内存配置。
- `WorkspaceViewModel` 串行提交配置，旧启动请求在发布前重验登记与修订。移除释放 watcher、清除当前内存状态，当前查询按有效观察键过滤；原历史与显式保护保留。换根保持旧索引，不将旧对象迁移到新版本。每轮异步保存同时捕获 watcher 和观察键，逐项处理前再验实例，避免另一根换路径后污染新版本。
- 手动会话保留开始时的原根与所属范围版本，不能在新根恢复旧会话；历史关联按观察键区分。移除、换根及同路径以新 Id 重新登记，均不终止会话或取消原根/显式依赖保护。旧会话只按 Id 与范围版本精确补绑原根；无法补绑的未结束记录令当前活动观察保持未知，直到用户明确结束。会话页可显示已移除/旧范围记录及原根，提供可操作的结束入口。
- `VolumeSpaceReader` 逐卷返回容量或具体错误，某卷不可访问不抹掉其他卷。`SpaceSurvey` 在本次根内按已读取身份去重，分别报告逐路径逻辑量、已知分配量、未知、重复路径、截断和未完成；身份集合上限 200,000。父子摘要和独立根不可直接相加，计量不表示可释放空间。
- `LocalStore` 保存最多 64 份显示摘要，每份最多 200 行、1 MiB；包含时间、原范围版本与完整度，不包含对象快照或批准。重启恢复恒为过期显示，不启动全盘监测，不恢复清理资格。
- 现有目录设置、项目卡片和概览接线；发现与盘点 scanner 绑定创建时根及范围版本。路径切换不沿用旧扫描器，扫描期间根变化明确过期或丢弃旧请求。
