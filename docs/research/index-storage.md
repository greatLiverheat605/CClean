# DEV-010 索引与容量验证

状态：DEV-010 基础只读闭环通过；不代表 DEV-019 的完整性能门槛通过。

## 已实现

- SQLite schema 1，WAL，500 文件一批事务；保留 30 天、最多 100,000 条变化。
- 不完整扫描保留原索引，不把未扫描到解释为删除。相同卷与文件身份去重，基线按身份持久保存；文件身份包含创建时间，降低 File ID 重用造成错误关联的风险。
- 总览单列逻辑大小、分配估算、相对登记基线净变化；有未知对象时不显示确定的净变化。文件表每页 200 项，虚拟化显示，并可查看完整路径。
- 每批索引重新检查用户可用量及自身 DB/WAL/SHM 预算；达到 80% 守卫或紧急空间阈值后停止采集，已有索引仍可查询。索引写入失败同样停采。
- 恢复监测会清除旧 revision，防止新的首轮快照被旧版本号跳过。索引只用于观察，未开放产品删除。

## 当前证据

Release 构建零警告、零错误。最新 FileMetadata / DeletionSafety / Storage / Discovery 共 15 项测试通过，覆盖初始量、增长、扫描缺口、消失、重启、同路径身份替换、跨根真实硬链接及 ADS。RuntimeBudget 另覆盖 80% 预算及卷比例阈值。

桌面合成项目已显示总览与文件表，文件完整路径、逻辑量与原始元数据一致。截图检查了布局与禁用的清理入口；文件表已改为按 B/KiB/MiB/GiB 显示，避免小文件四舍五入成零。新版每 5 秒自动刷新容量并检查静默期间预算。

100,000 文件规模测试在独立 D 盘合成目录运行，显式预算 1 GiB、保留空间 10 GiB，每文件 1 B。该样本检验文件数量和索引开销，不替代 20 GiB 基准。机器为 Ryzen 7 4800H、16 个逻辑处理器、约 15.4 GiB 可用物理内存配置、Windows 26100、NTFS。

首轮扫描 102,602 ms，索引 19,981 ms，未满足扫描 60 秒目标。复核后，扫描器复用当前目录已锁定的完整祖先链，避免每个文件重复打开祖先；最终句柄路径与身份校验仍执行。以同一批样本复扫：扫描 26,127 ms，索引 27,982 ms，100,000 文件与独立合成真值完全一致；DB/WAL/SHM 137,046,608 B，PoC 峰值工作集 136,425,472 B。同期另一个产品实例也在扫描并索引该合成根。这是热缓存结果，冷缓存与 20 GiB 结果待 DEV-019。

报告 ID：首轮 `20260917T093003211-6fdb1b1ec0ae4432ac69f8c9463a8d55`；复扫 `20260917T094610110-fe1ca64e8c6148cbb0c8fa23a7dc6fcf`。

10 分钟空闲测试针对 1 个已完成基线的合成登记根（1 文件），测试窗口保持总览页。同期宿主运行独立 fixture 生成等开发工作，CPU 只统计目标应用进程并折算为整机百分比。这不代表无其他负载的专用性能环境，也不代表 100,000 文件下的产品稳态。

小规模空闲报告 `idle-small-20260917.json`：604.617 秒、整机 CPU 平均 0.00969%、采样工作集峰值 119,742,464 B、自身文件峰值 73,989 B。该报告采于自动容量定时器接入前，不能作为最终新版验收。新版 100,000 文件索引已在产品实例与独立 SQLite 查询中确认完成，10 分钟空闲补充采样正在执行；最终 NFR-02 仍由 DEV-019 验收。原始报告保存在忽略提交的 `artifacts/performance/`。

新版大规模补测 `idle-large-20260917.json` 已完成：604.518 秒，整机 CPU 平均 0.04653%，采样工作集峰值 207,425,536 B（197.8 MiB），运行数据峰值 144,260,413 B。100,000 个文件已完成入库，5 秒自动容量/预算检查开启，窗口停留总览。CPU 与工作集满足当前目标，但内存距 200 MiB 上限较近，后续时间线与 20 GiB 完整产品仍需 DEV-019 复核。
