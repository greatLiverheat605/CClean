# CClean 个人使用说明 — 0.1.7

Windows 11 x64；当前正式安装版为 0.1.7，2026-09-22 已完成本机升级并保留原运行数据，2026-09-23 已核验正式启动、首页和项目页面。支持项目观察、空间盘点、只读版本比较和受控清理。已验证范围与未完成项见 [已实现功能审计](audit/implemented-features.md)；大样本内存门槛仍未通过，新版多日稳定性与 npm 正向 UI 验收仍未完成。

从开始菜单打开“CClean Internal”。默认安装位置为 `%LOCALAPPDATA%\Programs\CClean Internal`；运行数据默认位于 `%LOCALAPPDATA%\CClean`。

## 先选择项目

启动后展示项目卡片，可搜索名称或完整路径。卡片区分“已登记项目”“代码项目”“工具工作目录”；同一父目录下路径不同的版本不会合成一个项目。工具工作目录只表示发现过会话，不保证该目录本身是代码项目。

没有看到项目时，展开“发现更多项目”，选择存放项目的父目录并点击“发现 / 继续”。扫描只读取目录、属性和项目标记名称，不读取源码内容，不自动登记或启用清理；默认每批约 2 秒，可停止后继续。每次扫描范围最多保留 50,000 个目录、2,000 个项目候选，达到上限需改选较小范围。扫描会跳过系统、已识别的安装/依赖目录及链接；遇到项目根后不再深入其内部发现更多项目。

发现结果加入工作台，仅在本次运行保留；上次成功扫描的范围会保存，下次打开可以继续选择该范围重新发现。应用不会在启动后自动扫描全部 C 盘。没有支持的项目标记、被排除或无法读取的目录可能未被发现；可以在“项目与设置”登记明确范围。

普通会话子目录归入已知代码根或登记根，用户主目录不会作为所有项目的父项目。单独登记的子目录仍有自己的卡片；独立扫描加入的嵌套版本也保持独立。若仓库只登记了 `src`，父项目显示“部分子目录已监测”，请打开对应子项目查看历史，不会重复登记整个父目录。未登记且无重叠范围的项目可点击“加入持续监测”，此后才建立文件历史；此前离线变化无法补造。

## 项目概览与页面

点击项目后，概览与五个页签使用当前项目范围：

| 页面 | 用途与边界 |
| --- | --- |
| 开发时间线 | 已记录的文件变化、上下文依据和覆盖缺口；按时间、工具与依据筛选，支持列表与方向键选择。历史不是文件版本，不能回滚。 |
| 文件与空间 | 项目内相对路径、大小、增长和保护原因；每页最多 200 项，可查看完整路径或转入清理预览。 |
| 清理位置 | 打开即只读盘点一批，“盘点 / 继续”读取剩余范围；选目录检查清理资格，再打开候选确认清单。默认保护与规则覆盖均不是删除授权。 |
| 项目会话 | 支持格式的 Codex / Claude Code 自动发现记录及所属登记项目的手动会话；工具工作目录只列同一工作目录的自动会话，代码项目可含其子目录。 |
| 版本比较 | 主动选择另一个文件夹，只读检查独有文件与内容差异，不删除或移动项目。 |

项目概览的“已索引文件”是当前范围内索引记录数；逻辑大小和分配估算按已知文件身份去重，未知对象另列。“现存文件增长”只计算当前仍在范围内、可计量文件相对基线的大小变化，不是整个磁盘的历史净增减。暂停、基线未完成或扫描缺口会影响覆盖与时效，不应把未知量当成零。

清理候选摘要只代表当前复核位置的结果，并非整个项目可释放总量。位置盘点最多显示 200 行，一次资格检查最多接受 1,000 个文件；超过上限应选择更小位置。父子目录占用不能相加，目录大小也不等于可释放空间。执行前仍重新校验清单。

## 0.1.7 的观察故障处理

“已取得当前文件快照”不等于监视器仍能持续收到变化通知。0.1.7 在监视器报告非溢出故障、通知出现缺口、采集任务停止或监视器已关闭时，保持该范围的活动状态未知和清理保护；一次成功补扫不会自动清除监视器故障。已有索引仍可用于查看，但可能已经过期。

出现观察不可靠提示时，在“项目与设置”选择对应项目，使用“暂停 / 恢复”先暂停，再恢复，等待新监视器完成首扫。若仍不可访问或再次发生缺口，界面继续提示未知，需要处理目录可访问性后再重试。重建观察不补齐此前的文件变化过程；即使可靠观察恢复，活动会话、近期写入、npm 消费者和其他保护条件仍会独立阻止清理。

## 比较多个版本文件夹

打开项目的“版本比较”，选择另一版本并点击“开始只读比较”。两个目录必须互不包含，不能选择同一目录、父子目录、系统根或敏感数据目录。比较按相对路径进行；需要确认内容时，主动读取符合条件的普通文件并逐字节比较。

| 结果 | 如何理解 |
| --- | --- |
| 当前独有 / 另一侧独有 | 另一侧对应范围已完成盘点且未发现同相对路径；应保留该文件。 |
| 大小不同 / 内容不同 | 两侧文件不同，需人工核对和决定保留内容。 |
| 内容相同 | 本次逐字节比较及复核相同；不证明整个版本相同，也不授权删除目录。 |
| 未确认 | 读取缺口、敏感数据、特殊对象、占用、名称冲突、文件变化或预算限制；继续保护。 |

每侧最多盘点 10,000 项（文件和目录合计），两侧内容读取总计最多 512 MiB，单次时间预算 30 秒。可以取消；取消不会修改文件，也不会自动续算内容比较。结果可筛选，界面最多显示符合筛选的前 1,000 项，总数会另行注明。达到预算或存在缺口时，已显示的相同/独有结论只适用于通过检查的具体文件，不能据此推断未盘点位置。

系统对象不列出；已识别的凭据、Agent 私有数据、Git 元数据、数据库、JSONL 等不读取内容。链接、云占位、占用文件和其他不能完整确认的对象保持未确认；大小写名称冲突不会作为相同依据。结果只保留在界面内存，切换比较对象或项目后需重新比较。

## 空间盘点与清理

侧栏“空间与快清”不要求先登记项目：

- 空间盘点默认 C 盘，也可选项目父目录；每轮最多运行约 30 秒，可以停止 / 继续。最多保留 50,000 个目录、显示 200 行。按路径统计逻辑大小，硬链接可能重复；链接、云占位和不可访问对象跳过并计数。
- 项目版本名提示只比较同一父目录下的相似名称，例如 `app-v1` / `app-v2` / `app-backup`；名称不证明重复，也不会自动删除源码或旧项目。
- “快速清理临时文件”打开 Windows 磁盘清理，由系统列出分类并再次确认；“Windows 存储设置”打开系统分类。CClean 不自动勾选或确认下载、回收站等内容。
- 常见缓存只展示已盘点的标准位置，不保证识别工具自定义缓存；没有验证规则的位置不提供自动删除。

当前生产清理只有两类已验证规则，不承诺每次都有大容量可释放：

1. **旧 WSL 崩溃转储**：仅当前用户临时目录 `wsl-crashes` 的直接 `wsl-crash-*.dmp` 文件，保留最新时间的全部转储及最近 48 小时文件。删除后失去该次旧故障诊断内容，不删除 WSL 发行版、项目代码或开发依赖。
2. **专用独占 npm 11.19.0 缓存**：先将工具配置指向专用缓存，登记并确认工具版本及独占前提，再显式启用该根规则。默认/全局缓存不支持；仅 `content-v2` 与 `index-v5` 中符合条件的普通文件可能成为候选，至少保留 30 分钟。检测到 npm/node 消费者会保守保护，重建可能需要联网并增加下次安装耗时。

0.1.7 本轮仅修复可靠性，不扩大上述规则。npm 的完整正向 UI 验证仍需在独立客户机完成；本机存在消费者时展示保护原因属于预期行为，不等于清理流程已经获得正向验收。

在清理预览核对具体路径、候选数量和排除原因。源码、凭据、Agent 历史、活动、共享及特殊对象会被排除，全选不能绕过；普通 `node_modules`、`bin`、`obj` 或整个版本目录不会仅凭名称获准删除。清单有效期 5 分钟，永久删除前再次确认并逐项校验；文件不进入回收站。停止只影响后续项，不能恢复已删除内容；异常会停止后续删除。

清理记录区分已记录删除与重启后的观察结果。中断不会自动续删，必须重新预览后再确认。审计达到预算时停止清理，不自动删旧记录腾空间。

## 会话、设置与本地数据

自动会话发现支持本机部分 Codex / Claude Code JSONL 格式，只提取有限元数据；搜索支持项目路径、工具和会话 ID。自动发现的活动状态始终未知，不等于正在运行或已经结束，相关范围继续受保护。ZCode 及未识别格式使用手动会话。手动会话支持 Codex、Claude Code、ZCode 和通用工具标签；重启后的活动会话标为中断，恢复会建立新时间段。三工具关联仍是手动上下文，尚无 ETW/USN 进程证实，不能证明全系统无人使用。

浅色/深色在侧栏切换并自动记住；上次成功扫描的项目发现范围也保存在本地 `preferences.json`。发现候选、空间盘点与版本比较结果不持久化。详细文件变化最多保留 7 天/100,000 条，会话最多 1,000 条；空间预算不足会暂停采集，已有索引可能过期。更多数据范围见 [隐私说明](privacy.md)。

0.1.6 复用扫描缓冲和未变化快照、减少重复索引副本，并把容量汇总移到数据库以减少应用侧内存分配。实际大样本表现、多日稳定性和跨环境限制以 [功能审计](audit/implemented-features.md) 与 [发行验收](testing/release-acceptance.md) 为准。

0.1.7 减少索引加载的临时分配；实际 App 异常退出后的离线变化恢复已验证，10 万文件采样峰值 200.73 MiB 仍未达 200 MiB 门槛。加载内存改善伴随约 2.2 秒的独立探针加载代价。旧版 0.1.6 已完成 24 小时观察：2,880 样本、无超过 90 秒的采样空窗或失败事件，工作集峰值 176.98 MiB；私有内存和数据量有所增长，不能据此断言没有泄漏。旧版结果不替代新版多日验证；详情见 [可靠性补验](testing/reliability-017.md)。

退出会停止后续清理并等待当前项结束。升级前退出旧版本；旧程序遇到更高版本数据格式会拒绝写入。卸载只移除安装文件，不删除项目或本地索引、会话、设置和审计。左下“已实现功能审计”打开的是随包报告快照；本仓库文档已补充升级后的观察与安装证据，未修改已安装文件或已构建包。
