# 产品需求

版本：0.1 · 日期：2026-09-17 · 状态：方向已确认，技术细节待 PoC。

## 1. 问题与目标

Agent 在开发时会生成源码、依赖、构建产物、日志、临时文件与工具缓存。即使项目位于其他磁盘，工具数据仍可能写入 C 盘。传统磁盘分析工具能回答“哪里大”，但难以说明“哪个开发任务期间增长、关联依据是什么、现在能否清理”。

CClean 提供四个能力：发现空间变化、关联开发上下文、解释清理依据、验证实际空间变化。数据默认只在本机处理，不需要模型 API，不读取文件内容来判断垃圾。

目标用户是同时使用 Codex、Claude Code、ZCode 等工具的 Windows 开发者。首版聚焦单机、单用户与本地 C 盘 NTFS 卷。

## 2. 已确认需求与默认假设

| 项目 | 决定 | 状态 |
| --- | --- | --- |
| 可视化语义 | 项目 → Agent 会话 → 文件变化，可按时间回看 | 用户确认 |
| 清理策略 | 先预览；跳过活跃项目与未知来源；一键只执行确认过的规则 | 用户确认 |
| 工具范围 | Codex、Claude Code、ZCode；ZCode 为 zcode.z.ai | 用户确认 |
| 系统 | Windows 11 x64，本地桌面应用 | 默认假设，符合当前环境 |
| 监测范围 | C 盘总量 + 已登记项目、工具数据及缓存目录 | 推荐的 MVP 边界 |
| 初始权限 | 普通用户可用，增强监测按需请求管理员权限 | 设计决定 |
| 自动删除 | 首版关闭；低空间告警也不自动授权删除 | 设计决定 |

“会话”是 CClean 登记的一次开发活动，可以来自手动开始/结束、受控启动或经过验证的工具适配器。它不天然等于工具的聊天 ID，也不天然对应单独进程。

## 3. 关键场景

1. 开发者登记位于 D 盘的项目以及它在 C 盘使用的缓存目录，开始一个 Codex 会话；时间线展示会话期间监测范围内的增长。
2. 多个 Agent 同时工作时，用户切换项目与时间范围，定位增长最大的目录；共享缓存显示多个关联或“共享”，不重复计入总占用。
3. 用户点选一个文件簇，查看当前占用、观察到的变化、会话归因依据、是否受保护及可执行操作。
4. 一个项目停止开发后，用户预览可清理缓存；执行时出现新活动、文件变化或权限问题，相关项目自动跳过。
5. C 盘达到低空间阈值，工具提示并减少自身写入，用户进入已有索引生成的清理预览。
6. 工具无法识别某个 Agent 版本时，用户仍能登记目录并手动标记会话，界面显示“上下文关联，未经进程证实”。

## 4. 范围与优先级

P0 为发布 MVP 必须满足；P1 为后续增强；P2 为暂不实现。

| 编号 | 优先级 | 功能 | 验收摘要 |
| --- | --- | --- | --- |
| FR-01 | P0 | C 盘容量总览 | 总量、系统可用量、采样时间；不能把未扫描部分当零 |
| FR-02 | P0 | 项目登记与只读目录发现 | 支持多项目、目录重叠去重、跨盘关联；提供限额发现候选入口 |
| FR-03 | P0 | 基线扫描和增量校准 | 可暂停、取消；溢出与权限缺口可见；最终状态可收敛 |
| FR-04 | P0 | 会话管理 | 手动开始/结束、工具标签、异常结束识别，不依赖工具私有数据库 |
| FR-05 | P0 | 可解释归因 | 显示证实/上下文关联/共享/未知及证据，禁止猜测冒充证实 |
| FR-06 | P0 | 分支时间线 | 项目泳道、会话分支、聚合变化节点、时间筛选与详情 |
| FR-07 | P0 | 空间排名与搜索 | 按占用、净增长、最近变化排序，可按路径、项目和规则筛选 |
| FR-08 | P0 | 分类与保护 | 源码、凭据、会话、活跃对象、未知来源和特殊路径默认保护 |
| FR-09 | P0 | 清理预览 | 给出精确候选、风险、依据、估算值、排除原因和有效期 |
| FR-10 | P0 | 手动与一键清理 | 仅执行批准清单，执行前复核；不强杀进程、不扩大范围 |
| FR-11 | P0 | 清理审计与中断恢复 | 逐项成功/跳过/失败；取消停止后续项；崩溃后重新预览 |
| FR-12 | P0 | 低空间与自身预算 | 告警、紧急降级，数据库/WAL/日志总额受约束 |
| FR-13 | P0 | 三工具基础适配 | 三种工具均可标记会话与监测用户指定目录；列出验证版本 |
| FR-14 | P0 | 外部一键清理价值 | 至少一个真实外部工具缓存规则经过验证，可按安全条件进入常规一键清理 |
| FR-15 | P1 | 精确进程归因 | ETW PoC 通过后启用，显示覆盖范围与事件损失 |
| FR-16 | P1 | 广域变化恢复 | NTFS USN 用于补扫定位；卷权限不足时回退目录监测 |
| FR-17 | P1 | 增长预测与趋势 | 足够历史数据后估算耗尽时间，显示假设与不确定性 |
| FR-18 | P2 | 跨盘迁移与高级集成 | 工具支持的缓存迁移、WSL/Docker 内部清理、远端机器支持 |

FR-14 是必须通过的产品门槛，不能仅清理 CClean 自身文件，或仅支持单独确认的共享缓存清理，就宣称完成用户的一键清理需求。外部规则的具体对象、支持版本和可删除条件在 M0 实测后冻结；不通过则明确这一需求未完成，不能宣称完整 MVP。

## 5. 首版不包含的能力

- 拦截或限制任意进程写盘、内核驱动、保证磁盘永不写满。
- 文件内容版本库、Git 提交回滚、代码 diff；图形分支只表达开发上下文和时间。
- 默认全盘高频递归扫描；系统保护目录的强制访问或删除。
- 自动判断所有未知目录是否“垃圾”，或用 LLM 直接授权删除。
- 自动终止 Agent、编辑器、包管理器，自动清除会话和凭据。
- 修改 Windows 更新、注册表、休眠或页面文件配置。
- 直接删除或压缩 WSL/Docker 的虚拟磁盘；首版可将它们标为不透明大文件。
- 云端遥测、账户系统、远程控制、无人值守永久清理。

## 6. 指标词典

| 名称 | 定义 | 不能代替什么 |
| --- | --- | --- |
| 系统可用空间 | Windows 为当前用户报告的 C 盘可用字节 | 不等于目录大小之和 |
| 当前文件大小 | 文件逻辑长度 | 不等于实际分配空间 |
| 估算占用 | 可取得的分配信息，按文件身份去重 | 不承诺唯一物理簇占用 |
| 净增长 | 同一监测集合两次有效快照的大小差 | 不等于累计写入量 |
| 观察到的写入量 | 可用时累计 ETW 写请求字节，标注覆盖与损失 | 不等于增长、持久化写入或磁盘硬件写放大 |
| 待清理估算 | 通过规则的候选对象预计可释放的范围 | 不等于保证释放量 |
| 实测可用量变化 | 清理后系统可用量减清理前系统可用量 | 受同时进行的其他写入/删除影响 |

目录监测不提供可靠累计写入量时，显示“未采集”，不能用 `abs(大小差)` 拼凑。权限不足、基线未完成、采集缺口对应“未知/不完整”，不能显示为零。

## 7. 可用性和资源目标

以下是 M0 后需要校准的目标，以 Windows 11 x64、4 核以上、16 GiB 内存、本地 SSD、100,000 个文件/20 GiB 合成监测集为初始基准。所有测试需记录实际机器、文件分布、其他负载和采集模式。

| 编号 | 目标 | 验证方法 |
| --- | --- | --- |
| NFR-01 | 稳态变化到界面显示 P95 ≤ 2 秒 | 合成事件时间与渲染时间差 |
| NFR-02 | 空闲 CPU 平均 ≤ 整机 1%，稳态工作集 ≤ 200 MiB | 基线完成后连续 10 分钟采样 |
| NFR-03 | 100,000 文件初次扫描目标 ≤ 60 秒，可取消 | 冷/热缓存各测，不能锁住 UI |
| NFR-04 | 可见图节点最多 500 个，文件列表分页/虚拟化 | 压测大量会话和文件，无无限追加 |
| NFR-05 | 100,000 文件索引下，DB+WAL+SHM ≤ 300 MiB，日志 ≤ 50 MiB | 批量写入与保留策略联合测试 |
| NFR-06 | 保护对象误删为 0，已批准集合外删除为 0 | 竞态、链接、并发活动与崩溃用例全部通过 |
| NFR-07 | 溢出后不伪造历史；补扫后当前状态一致 | 与静默期独立枚举比对，缺口持续可见 |

更大数据集达到容量预算时暂停扩展索引或降低粒度，并显示覆盖受限；不能靠无限扩容满足扫描范围。重度扫描和 ETW 模式单独报告资源指标。

## 8. 业务验收边界

用户必须能完成“登记 → 观察增长 → 理解来源依据 → 预览 → 安全执行 → 查看实测结果”的闭环。若无候选，一键入口应解释排除原因，不能为提供清理数字而放宽保护。

首版只对已登记、可访问、经过验证的范围作出判断。未登记项目、后台共享服务和未知工具版本导致的不确定性必须可见。工具帮助保持 C 盘可用，但不具有系统级写入额度管控能力。
