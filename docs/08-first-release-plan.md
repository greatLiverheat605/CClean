日期：2026-10-23（Asia/Shanghai）。状态：用户选择 A，首批范围已确认（D-12），已进入实施与分项验证。下文交付范围作为当前基线；工程做法和规则资格通过实施验证。业务开发与隔离验证已开始，未安装新版或清理现有用户文件，旧验收状态保留。当前入口：[首批执行计划](../.codex/plans/current/2026-10-23_cclean-first-release.md)。

## 1. 交付目标与当前起点

用户打开分类工作台，能判断内容是什么、是否重要、处理会有什么影响；保留自己需要的内容，核对具体清单并完成符合规则的清理，最后看见哪些成功、哪些没处理及其原因。

当前 0.1.7 已有项目发现、盘点、观察、时间线、只读版本比较和受控执行基础。93 项回归通过；用途分类、逐项保留、统一清理闭环与正式 npm UI 验收仍有缺口，内存峰值 200.73 MiB 超过原 200 MiB 门槛。首批复用这些基础，围绕实际操作补齐，不能把现有页面数换算成完成率。

| 已确认方向 | 首批落地范围 |
| --- | --- |
| 看懂并放心清理优先，Agent 写入追踪仍是主线 | 首批完成空间解释与可控清理，以及所依赖的轻量观察；之后深化活动联动和进程追踪 |
| 分类工作台 | 用途类别、内容说明、影响和本次选择同屏联动；独立预览后确认执行 |
| Windows 本机、跨盘、覆盖所有 Agent 的兼容目标 | 逐卷展示、已知工具识别与自定义目录纳入；明确未识别及未覆盖范围，不承诺任意工具数据都可清理 |
| 手动启动、后台观察、关闭进托盘、明确退出 | 首批完成可用的范围管理、暂停/恢复、托盘与单实例生命周期；不默认开机启动 |
| 本次 CClean 压测数据保留报告与复现方法 | 首批新增规则仅验证这一种；现有专用 npm 和旧转储规则完成闭环回归 |

## 4. 首批核心操作与状态

1. 打开工作台，看见各卷状态、观察状态和本次盘点覆盖；选择用途类别，可用项目/工具/磁盘筛选。
2. 查看某类内容的用途、重要性、处理影响及依据；不合格或未支持的内容说明具体原因与下一步。
3. 保留类别或具体对象，形成“本次选择”；有关联依赖的对象按已验证组合处理，不能偷偷扩大选择。
4. 生成独立预览，核对本批路径、数量、估算和各规则影响，明确永久删除、不进回收站；确认仅对本批具体对象有效。
5. 执行时显示进度与停止入口；停止只阻止后续项。完成后查看逐项结果、逐卷变化与未处理范围，按需要重新预览剩余内容。

关键状态：未盘点、扫描中、已完成/部分完成、无候选、待确认、执行中、部分成功、已停止、清单失效、失败。切页、快速切换筛选、重新扫描与重复点击不能让旧异步结果覆盖新范围，也不能产生第二个执行器。

大样本必须自动形成可执行的有限批次，用户不需要靠手工选目录绕过现有 1,000 项限制。展示本批处理量、已知剩余与未扫描范围；分页只是展示方式，不是隐式批准下一页。保持现有 5 分钟有效期、审计/资源预算和逐项校验；合理批次容量通过实测确定，不能简单取消限制。后续批次重新预览确认，不承诺一次清空 100,002 个文件，也不能把截断结果写成全目录结果。

保留选择应在后续预览中继续生效；新增文件不自动加入已经批准的清单。文件身份、活动、规则版本或保护状态发生影响资格的变化时，按现有安全协议停止或要求重新预览。

## 7. 后续路线与本次评审重点

- **随后深化 Agent 活动。** 完善增长到目录/文件的联动，区分上下文关联、未知和进程证实；按需增强追踪先独立 PoC，验证权限、事件损失、PID/子进程关联和资源开销后再接入。
